# นำเข้าข้อมูลแผนก / หน่วยงาน / พนักงานจริง

ไม่ต้องรู้ UUID เอง — แค่กรอก CSV ตาม template แล้วให้ SQL จับคู่ให้อัตโนมัติ

## ภาพรวมขั้นตอน
1. (ถ้าต้องการ) ล้างข้อมูลตัวอย่างเดิม
2. เพิ่มคอลัมน์ `unit_code` ในตาราง `units` (รันครั้งเดียว)
3. ตรวจ/แก้ไฟล์ `units_template.csv` (มีการจับคู่แผนกให้อัตโนมัติล่วงหน้าแล้วบางส่วน)
4. อัปโหลด CSV เข้า Supabase ผ่าน Table Editor
5. รัน SQL ย้ายข้อมูลให้จับคู่แผนกอัตโนมัติ

---

## ขั้นตอนที่ 1 — ล้างข้อมูลตัวอย่างเดิม (ทำหรือข้ามก็ได้)
เปิด SQL Editor → รัน `00_clear_sample_data.sql`
⚠️ จะลบคำขอ/ประวัติที่เคยทดสอบไว้ด้วยทั้งหมด — ถ้าจะเก็บของเดิมไว้ ข้ามขั้นตอนนี้

---

## ขั้นตอนที่ 2 — เพิ่มคอลัมน์ unit_code
เปิด SQL Editor → รัน `03_add_unit_code_column.sql`
(เก็บรหัสหน่วยงานเดิมจากระบบเก่าไว้ในตาราง `units` เพื่ออ้างอิงย้อนหลัง)

---

## ขั้นตอนที่ 3 — ตรวจ/แก้ไฟล์ units_template.csv

ไฟล์ `units_template.csv` ในโฟลเดอร์นี้ **จับคู่แผนกให้อัตโนมัติไว้แล้วบางส่วน**
(คอลัมน์ `dept_code`) จากชื่อหน่วยงานที่ให้มา แต่บางแถวจับคู่ไม่ได้หรือไม่มั่นใจ

เปิดไฟล์ `units_matched_for_review.csv` **เพื่อตรวจสอบ** (มีคอลัมน์ `confidence`
บอกความมั่นใจ: `needs_review` / `contains` / `fuzzy` / `prefix` / `exact` —
เรียงจากที่ต้องตรวจก่อนไปหลังสุดแล้ว):

- แถวที่ `dept_code` ว่าง (needs_review) → ต้องกรอกรหัสแผนกเองใน `units_template.csv`
- แถวที่ `confidence = contains` หรือ `fuzzy` → ควรเช็คว่าจับถูกแผนกหรือไม่

**จุดที่ควรตรวจเป็นพิเศษ:** หน่วยงานที่ชื่อมีคำว่า "Mold" หรือพิมพ์ตกหล่น
(เช่น 210-1, 215-1) มักถูกจับคู่ผิดไปที่แผนกที่มีชื่อสั้นกว้างเกินไป
ให้เช็คคอลัมน์ `matched_dept_name` ในไฟล์ review ว่าตรงกับความเป็นจริงหรือไม่

แก้ `units_template.csv` ให้ `dept_code` ถูกต้องครบทุกแถวก่อนไปขั้นตอนถัดไป

### เกี่ยวกับ departments_template.csv
ปรับให้เหลือแค่ `code,name` แล้ว (ตัดคอลัมน์ `color` ว่างออก เพราะตารางมีสีเริ่มต้นให้อยู่แล้ว
ถ้าปล่อยคอลัมน์ว่างไว้ อาจชนกับข้อจำกัด NOT NULL ตอน import)

---

## ขั้นตอนที่ 4 — อัปโหลด CSV เข้า Supabase

### 4.1 นำเข้าแผนกก่อน (ตรงเข้าตารางจริงได้เลย)
Table Editor → ตาราง `departments` → Insert → **Import data from CSV** → เลือก `departments_template.csv`
→ ตรวจว่าคอลัมน์ `code`, `name` จับคู่ถูกต้อง → Import

### 4.2 สร้างตารางพักข้อมูล
SQL Editor → รัน `01_staging_tables.sql`

### 4.3 อัปโหลด units และ employees เข้า staging
Table Editor → ตาราง `staging_units` → Import data from CSV → เลือก `units_template.csv` (**เวอร์ชันที่แก้ไขแล้ว**)
Table Editor → ตาราง `staging_employees` → Import data from CSV → เลือก `employees_template.csv`

---

## ขั้นตอนที่ 5 — ย้ายข้อมูลเข้าตารางจริง

SQL Editor → รัน `02_load_from_staging.sql`

ไฟล์นี้จะ:
1. ตรวจก่อนว่ามี `dept_code` ไหนพิมพ์ผิด/ไม่ตรงกับแผนกที่มีอยู่หรือไม่ (ถ้าเจอ query แรกจะคืนแถวออกมา — แก้ CSV แล้วอัปโหลดใหม่ก่อนรันต่อ)
2. ย้ายข้อมูลจาก staging เข้าตาราง `units` (พร้อม `unit_code`) และ `employees` จริง พร้อมจับคู่ `department_id` อัตโนมัติ
3. ลบตาราง staging ทิ้ง
4. แสดงจำนวนแผนก/หน่วยงาน/พนักงานทั้งหมดให้ตรวจสอบ

เสร็จแล้ว เปิด `index.html` — ตัวเลขหน้าแรกควรตรงกับข้อมูลจริงที่นำเข้า

---

## หมายเหตุ
- นำเข้าเพิ่มทีหลังได้เรื่อยๆ (รัน `01_staging_tables.sql` ใหม่ทุกครั้งก่อนอัปโหลดรอบใหม่)
- พนักงาน/หน่วยงานที่ซ้ำ (employee_code หรือ unit_code ซ้ำ) จะถูกข้ามอัตโนมัติ ไม่ insert ซ้ำ
- CSV รองรับภาษาไทยปกติ ตรวจแค่ว่าบันทึกเป็น UTF-8
